# По местам Вяйнямёйнена

Готовый статический сайт для GitHub Pages: виртуальная экскурсия-лонгрид по мотивам эпоса «Калевала». Проект собран на **Vite + TypeScript** без серверной части и работает как обычный статический сайт после `npm run build`.

## Что реализовано

- главный экран с морским фоном `public/background.png`;
- загрузочный экран с анимированным Сампо, который появляется при открытии страницы и плавно исчезает после готовности интерфейса;
- интерактивная карта из пяти регионов `map_1.png` — `map_5.png`;
- расположение регионов карты:
  - `map_1` — слева сверху;
  - `map_2` — справа сверху;
  - `map_3` — слева снизу;
  - `map_4` — по центру;
  - `map_5` — справа снизу;
- лёгкое покачивание регионов на воде;
- визуальная обратная связь при наведении, фокусе с клавиатуры и активном регионе;
- tooltip/карточка региона с названием и кратким описанием;
- переход по клику на регион к связанному экспонату;
- пять экспонатов, в каждом есть картина, подпись, фрагмент руны, комментарий, иконка рунопевца и аудиокомментарий;
- подсказка первого визита «Нажми на меня, и я расскажу об этом экспонате», которая скрывается после закрытия или запуска аудио и сохраняет состояние в `localStorage`;
- единый аудиоплеер: при запуске нового комментария предыдущий аудиофайл останавливается;
- адаптивная вёрстка без горизонтального скролла на мобильных экранах;
- workflow для публикации на GitHub Pages.

## Данные и ассеты

Текущая версия уже содержит необходимые для готового сайта ассеты:

- `public/background.png` — фон морской глади;
- `public/icon_audio.png` — иконка рунопевца/аудио;
- `public/map/map_1.png` … `public/map/map_5.png` — регионы карты;
- `public/pictures/pic_1.jpg` … `public/pictures/pic_5.jpg` — изображения экспонатов;
- `public/sound_comment/s_comm_1.mp3` … `public/sound_comment/s_comm_5.mp3` — аудиокомментарии.

Текстовые данные экспонатов находятся в `src/data/exhibits.ts`. Если исходная таблица `db_pic-comment.xlsx` изменится, нужно синхронизировать данные в этом файле и проверить соответствие путей к изображениям и аудио.

## Установка зависимостей

```bash
npm install
```

## Локальный запуск разработки

```bash
npm run dev
```

После запуска Vite покажет локальный адрес, обычно `http://localhost:5173/`.

## Сборка проекта

```bash
npm run build
```

Готовая статическая версия появится в папке `dist/`.

## Предпросмотр production-сборки

```bash
npm run preview
```

По умолчанию Vite Preview запускается на `http://localhost:4173/`. Для явного адреса можно использовать:

```bash
npm run preview -- --host 127.0.0.1
```

## Деплой на GitHub Pages

Проект готов к публикации через GitHub Actions. В `vite.config.ts` задано `base: './'`, поэтому Vite собирает относительные пути, подходящие для GitHub Pages в репозитории с любым именем.

1. Откройте репозиторий на GitHub и перейдите в **Settings → Pages**.
2. В блоке **Build and deployment** выберите **Source: GitHub Actions**.
3. Убедитесь, что изменения попадают в ветку `main`: workflow `.github/workflows/deploy.yml` запускается при каждом `push` в `main`.
4. После push GitHub Actions автоматически выполнит `npm ci`, `npm run build`, загрузит папку `dist/` как Pages artifact и опубликует сайт.
5. Результат деплоя можно посмотреть:
   - в репозитории на вкладке **Actions** — запуск `Deploy to GitHub Pages` покажет статус сборки и публикации;
   - в **Settings → Pages** — после успешной публикации GitHub покажет URL сайта;
   - в карточке environment **github-pages** внутри завершённого workflow run.

## Финальная проверка перед публикацией

Рекомендуемый минимум перед деплоем:

```bash
npm install
npm run build
npm run preview
```

После запуска preview проверьте главную страницу, карту, переходы к пяти экспонатам, подсказку первого визита, воспроизведение аудиокомментариев и мобильную ширину экрана.

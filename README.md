# По местам Вяйнямёйнена

Готовый статический сайт для GitHub Pages: виртуальная экскурсия-лонгрид по мотивам эпоса «Калевала». Проект собран на **Vite + TypeScript** без серверной части.

> Важно: бинарные ассеты не входят в pull request. После мержа пользователь должен самостоятельно положить изображения, аудио и таблицу-источник в нужные папки.

## Что есть на странице

- главный экран, рассчитанный на морской фон `public/background.png`;
- загрузочный экран с плавным исчезновением;
- интерактивная карта из пяти регионов `map_1.png` — `map_5.png`;
- подсветка, подъём, покачивание и tooltip при наведении/фокусе на регион карты;
- плавная прокрутка от региона карты к связанному экспонату;
- пять экспонатов: картина, подпись автора/названия, фрагмент руны, комментарий;
- аудиокомментарии по клику на иконку рунопевца;
- подсказка «Нажми на меня, и я расскажу об этом экспонате», которая показывается один раз и сохраняет состояние в `localStorage`;
- адаптивная вёрстка и поддержка клавиатурной навигации.

## Какие ассеты нужно добавить вручную

Папки для будущих ассетов уже сохранены через `.gitkeep`, но сами бинарные файлы намеренно не коммитятся. Перед локальным просмотром и деплоем добавьте вручную:

- `public/background.png` — фон морской глади для главного и загрузочного экранов;
- `public/icon_audio.png` — иконка рунопевца/аудио;
- `public/map/map_1.png` — регион карты слева сверху;
- `public/map/map_2.png` — регион карты справа сверху;
- `public/map/map_3.png` — регион карты слева снизу;
- `public/map/map_4.png` — центральный регион карты;
- `public/map/map_5.png` — регион карты справа снизу;
- `public/pictures/pic_1.jpg` … `public/pictures/pic_5.jpg` — изображения экспонатов из колонки `pictures`;
- `public/sound_comment/s_comm_1.mp3` … `public/sound_comment/s_comm_5.mp3` — аудиокомментарии из колонки `sound_comment`.

Исходная таблица `db_pic-comment.xlsx` также не входит в PR. Данные из неё уже перенесены в текстовый файл `src/data/exhibits.ts`; если таблица изменится, обновите этот файл вручную или отдельным скриптом без коммита `.xlsx`.

## Установка зависимостей

```bash
npm install
```

## Локальный запуск

```bash
npm run dev
```

После запуска Vite покажет локальный адрес, обычно `http://localhost:5173/`.

## Сборка проекта

```bash
npm run build
```

Готовая статическая версия появится в папке `dist/`. Если ассеты ещё не добавлены вручную, сборка всё равно проходит, но изображения и аудио на странице будут ожидать соответствующие файлы в `public/`.

## Предпросмотр production-сборки

```bash
npm run preview
```

## Деплой на GitHub Pages

Проект настроен с `base: './'` в `vite.config.ts`, поэтому собранные пути относительные и подходят для GitHub Pages даже без знания имени репозитория.

### Вариант 1: ручной деплой папки `dist/`

1. Добавьте ассеты вручную в `public/` по списку выше.
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Соберите проект:
   ```bash
   npm run build
   ```
4. Опубликуйте содержимое папки `dist/` в ветку или источник, выбранный в настройках GitHub Pages.

### Вариант 2: GitHub Actions

Можно добавить workflow, который выполняет `npm ci` или `npm install`, `npm run build` и публикует папку `dist/` через официальный механизм GitHub Pages. В настройках репозитория выберите **Settings → Pages → Build and deployment → GitHub Actions**.

## Если репозиторий будет опубликован в корне домена

Текущая настройка `base: './'` универсальна. Если сайт будет жить строго в корне пользовательского домена, можно оставить её без изменений. Если позже понадобится абсолютный base, измените `base` в `vite.config.ts`.
